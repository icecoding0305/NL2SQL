要求：
- 只规划 SELECT，不规划写操作、DDL、存储过程或外部调用
- SCHEMA_DATA 只能包含本次查询裁剪后的 query_mschema 和业务语义，严禁索取、推断或使用完整数据库 Schema
- target_tables、字段只能来自 SCHEMA_DATA.query_mschema.tables；未出现的表和字段一律视为不可用
- 严格采用 query_mschema.tables 的角色和最小关系子图，bridge 表不是替代主表
- JOIN 只能采用 SCHEMA_DATA.query_mschema.relations 中的关系，并严格使用给出的两侧字段；没有合格关系时不得猜测 JOIN
- 过滤字段必须对应 SCHEMA_DATA.query_intent.filters；数值比较只能使用数值字段
- SCHEMA_DATA.semantic_graph 是用户问题的唯一语义事实，不得重新解释或遗漏其中的高影响原子
- SCHEMA_DATA.query_mschema.semantic_bindings 是已完成的物理绑定，计划必须严格采用其中的表、字段、操作符和值
- SCHEMA_DATA.semantic_graph.outputs 是用户明确要求的返回内容；其中 required=true 的每一项都必须在 output_fields 中实现，禁止用实体主键替代姓名、地址等明确属性
- SCHEMA_DATA.query_mschema.output_bindings 是输出要求的物理字段绑定；output_fields 必须严格使用 bindings 中的全部字段，并把对应 output_id 写入每个字段的 source_output_ids
- output_bindings.binding_mode=expanded 表示用户使用了宽泛的结果概念，必须同时返回 bindings 中的所有同主体字段并采用各自 label 作为业务别名；不得因此扩展筛选、分组、排序或 JOIN 字段
- 每个 filter/join/metric 必须填写 source_atom_ids；covered_atom_ids 必须与这些操作实际实现的高影响 atom_id 完全一致
- covered_output_ids 必须与 output_fields 实际填写的 source_output_ids 完全一致，并覆盖全部 required output id
- 必须显式填写 output_fields 和 output_grain。output_fields 只描述最终返回列；output_grain 描述每一行代表实体、明细记录、分组聚合还是全局聚合
- output_grain.level=entity/record 时必须给出可用的 keys；level=aggregate 时 keys 必须与 group_by 完全一致；level=global 时 keys 必须为空
- semantic_graph 中的 group_by、order_by、limit 是用户查询契约，必须分别原样落实到 QueryPlan.group_by、order_by、limit，不得遗漏
- output_bindings 中的 aggregation 是已经确认的计算方式；同一个物理字段可以分别生成 SUM、AVG 等多个独立 output_fields，不得合并
- 普通行级条件写入 filters；累计、合计、平均、最大、最小等聚合结果条件必须写入 having，并声明 aggregation，禁止写入 WHERE
- filters.scope 必须区分 row/cohort/measure；多事实查询中 cohort 条件用于限制最终实体集合，measure 条件只影响所属指标子计划
- SCHEMA_DATA.query_mschema 是唯一可用 Schema，必须只以它规划字段与关系；不得请求完整 Schema 或从数据库常识猜测额外字段
- status、exists、not_exists 条件必须落实为可执行过滤/连接语义；无法实现时降低置信度并让校验失败，禁止静默删除
- 正向 exists 应把父 atom_id 标注到实现该存在关系的 join/filter；服务端会在所有子条件已完整实现时做确定性补全。not_exists 不会自动补全，必须明确规划反连接语义
- 当 query_intent.query_type=fact_filter 且用户要求返回实体信息/列表时，条件只写入 filters，metric_logic 必须为 null；“统计”不能被擅自理解为 SUM/COUNT
- existence 查询中的“没有/不存在”必须规划为反连接语义（LEFT JOIN 后目标键 IS NULL），不得误用普通 INNER JOIN
- 多表字段必须标明所属表；同名字段必须显式指定 table
- 复合指标的 metric_logic.definition 和 columns 必须与 TERM_DATA 完全一致
- 时间条件使用字段的 type/time_granularity，不能把字符串日期和日期类型混用
- join_type 只能是 inner/left/right/full/cross；filter operator 只能使用 QueryPlan 支持的标准运算符
- confidence 是对当前计划事实完备性的评估；缺少口径或 JOIN 事实时必须降低
- metric_logic 只能为 null，或严格使用 {{"metric_name":"...","definition":"...","columns":["table.column"],"expression":null,"source_atom_ids":["atom_id"]}}；禁止使用 name、field 等未定义键
